# Chat 前端域

聊天前端只负责把用户送进一段角色会话，并把消息收发链路跑顺。

## 文件

- `ChatPanel.vue`：聊天消息、输入框、角色切换和调试导出入口。
- `api.ts`：visitor、角色、session、chat send、story pane 和 export 请求。
- `useChatSession.ts`：visitor 初始化、角色本地存储 key、会话恢复、发送消息、滚动到底部和 memory postprocess 等待。

## 运行边界

1. 初始化 visitor 和角色列表。
2. 以 `visitor_id + character_id` 创建或恢复 session。
3. 发送用户消息，立即接收主回复。
4. 把后端返回的 memory pane、state、bond 快照交给对应展示层。
5. 主回复后等待 memory postprocess 诊断和 Prompt Stack 刷新，但不在 chat 域里编辑 memory，也不在这一步额外刷新 state/bond。

## 请求与反馈

- 本轮模型回复和本地备用回复分别标记；历史消息没有来源记录时不推断来源。
  来源标签暂存在当前页面内存中，重新加载会话会保留，整个页面刷新后不保证保留；本轮没有修改数据库格式。
- 用户发送中的消息标为“正在发送”；请求失败后标为“未确认是否送达”，恢复输入并暂停重发。
  用户先点击“重新加载”核对服务端记录，再决定是否重发。客户端不自动重试，也不保证服务端恰好处理一次。
- 按访客与角色保留当前页面内的草稿；切换后返回仍可继续编辑。页面刷新或关闭不保证保留未发送草稿。
- 每次打开会话都会使旧请求失效。旧回复、错误、后台分析结果不覆盖新会话；同一会话只接受最新一轮的后台结果。
- 切回仍有发送请求未结束的会话时，需稍后重新加载再继续发送，避免重复提交。
- “回复已保存”和“后台整理完成”是两个状态。后台等待失败不把已保存回复标为发送失败。
- 会话关联的素材、小说列表、章节版本列表，以及记忆编辑结果，都检查其目标是否仍然有效。

## 验证

`npm test` 运行 Node 内置测试，用现有 esbuild 打包 TypeScript 测试，不新增测试框架。
测试覆盖会话乱序响应、发送失败与输入恢复、切换角色、备用回复标记、后台分析乱序和错误提示。
网络使用替身，不调用真实模型，也不写入旧数据。

## 不放这里

- 记忆过滤、编辑、冻结和 Prompt Stack 展开，归 `relationship/`。
- 恋爱人格测试，归 `relationship/personalityTest/`。
- Story Canvas、项目事件池、章节和版本，归 `novel/`。
